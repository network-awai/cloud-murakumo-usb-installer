# Data-preserving USB updates

Boot the new AiueOS USB in UEFI mode and choose **Update existing AiueOS (keep data)**. Choose the existing internal AiueOS disk and select Update. A new installation is a separate, explicitly destructive action.

The update checks the selected disk identity, AiueOS root/EFI filesystem types and labels, installation UUID binding, previous system profile and bound boot entry, offline closure validity, free space and absence of an unfinished automatic-update trial. Windows-only, BIOS, removable, mounted and ambiguous targets are refused. No partitioner or filesystem formatter is called by the update path.

The update installs the prebuilt system without Internet, retains `/var/lib`, NetworkManager profiles, device/account identity, authorized SSH keys and the owner update configuration. It saves boot files and Nix configuration under `/var/lib/aiueos-usb-update`, roots the previous generation against garbage collection and retains its boot-menu entries and kernels. A caught installation error restores the previous profile and boot files. This is manual recovery, not a claim of power-loss-safe transactional updates or hardware watchdog qualification.

After restart and USB removal, open **AiueOS updates** from the setup screen. **Refresh status** reloads the display; **Check updates now** invokes the signed updater according to the owner's existing policy and can apply/restart when its gates permit. An unconfigured standalone Node can enable periodic signed checks from this screen. Public production verification keys are shipped; private signing keys are never shipped. Existing journals are never replaced during provisioning. Automatic activation remains held until real hardware recovery qualification is recorded by an operator. Missing space, trust, clock or recovery requirements cannot be bypassed by pressing Check.

The USB source is newer than the existing production sequence 4. A successful manual update advances an existing installed-sequence floor monotonically to at least 4 while retaining all other journal fields. A newer signed production release is still required for distributing this source through the automatic channel. USB writing and successful physical Node updates must be reported separately from source and VM verification.
